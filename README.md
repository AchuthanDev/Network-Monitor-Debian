# Network Monitor Debian

Network Monitor Debian is a self-hosted Debian server monitoring platform focused first on accurate accounting of Internet traffic generated by the server itself.

The first milestone is deliberately narrow:

- Count Debian server Internet download and upload separately from LAN, Docker internal, and loopback traffic.
- Attribute traffic to processes and Docker containers in later phases.
- Store historical minute, hourly, and daily records so unexplained ISP usage can be investigated later.
- Never display fake production monitoring data. If collection is unavailable, the UI and API report `unavailable`.

This project does not claim to measure total household SLT or router usage. Phones, TVs, laptops, and other LAN clients can use Internet independently unless a future gateway/router module is enabled.

## Current Phase

Phase 1: project bootstrap.

Included now:

- Go collector skeleton.
- Go API skeleton with health endpoints.
- React, TypeScript, Vite frontend skeleton.
- PostgreSQL Docker Compose environment.
- Feature-first project layout.
- Architecture and network accounting documentation.
- Initial LAN/Internet/Docker/loopback classification tests.
- GitHub Actions CI definition.

Real traffic collection is planned for Phase 2 and must pass controlled LAN/public/Docker validation before dashboard totals are treated as usable.

## Quick Start

```bash
cp .env.example .env
docker compose -f deployments/docker/compose.yml up -d
```

Default local URLs:

- Web: `http://localhost:18000`
- API: `http://localhost:18080`
- Collector health: `http://localhost:19091/healthz`

## Development

```bash
make test
make lint
make build
make docker-up
make docker-down
```

Go is not required on the host for Go tests or Go builds; the Makefile uses a pinned `golang:1.23.10-alpine` container. Node.js and npm are required for frontend checks.

## Security

The collector is the only component expected to need elevated host visibility. The API, frontend, and database should run without host network privileges. No component should modify firewall, routes, DNS, Docker daemon settings, or interface configuration without an explicit deployment step.
